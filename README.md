# coin_auto
BTC 자동매매 봇 — OKX USDT 무기한 선물 (격리 마진, 레버리지)

규칙 (research_okx_short.txt, OKX 2021-03~2026-09-09 검증 CONF=6 1배 +135% / MDD −23%, 3배 +492% / −52%):
- 용어: 롱 = 상승에 거는 것, 숏 = 하락에 거는 것. 청산은 방향이 아니라 행동이다
- 국면: 마지막 완성 일봉 8개 지표 중 CONF(.env, 현재 6)개 이상 강세면 롱 국면, CONF개 이상 약세면 숏 국면 (동시 성립 불가)
- 진입: 롱 = 롱 국면 & 4h 종가가 직전 12봉 고가 돌파 · 숏 = 숏 국면 & 4h 종가가 직전 12봉 저가 이탈
  `EXTREME_MIN`(기본 0=끔): 4h 극단 점수(RSI·볼린저·스토캐스틱·도치안·꼬리·거래량·ATR 7개) 하한.
  OKX 표본에서는 켜면 좋아 보였지만(검증 Sharpe 1.29→1.35) **비판적 검증에서 기각됐다** — 다중 검정 보정 시
  실효 p≈0.30, 10년 Bitstamp 표본 개선 없음, 7규칙 중 1개만 일하고 1개는 해롭다 (research_bias.txt). 점수는 표시만 한다
  숏은 `ALLOW_SHORT=0` 으로 기본 꺼짐 — 자리는 계산·표시하되 주문은 내지 않는다
  (research_both_sides.txt: 숏만 1배 −72%, 롱+숏 1배 −34%, 롱만 +135%. 하락 국면에서조차 롱 승률 41% > 숏 23%)
- 청산: 롱은 4h 종가가 직전 6봉 저가 이탈 or 롱 국면 붕괴 · 숏은 직전 6봉 고가 돌파 or 숏 국면 붕괴
- 진입 타이밍: 돌파당한 고가를 하한으로 보고, 1분봉이 그 선을 지키거나 되찾을 때만 매수. 다음 4h 봉까지 못 지키면 자리 포기
  (`ENTRY_FLOOR=0` 이면 신호 즉시 매수. research_entry_timing.txt: 3배 +1,156% vs 즉시매수 +492%)
- 10분마다 판단 (진입 / 청산 / 홀드 중 하나). 같은 자리로 Claude 를 부르는 것은 한 번뿐
  갱신주기 10분은 측정값이다 — 1~30분은 차이가 노이즈, 60분부터 자리를 놓치기 시작한다 (`make lat`)

```
make run        포트 정리 후 대시보드+봇 실행 (http://localhost:8000)
make stop       포트 8000 프로세스 종료
make on/off     자동실행 켜기/끄기 (실행 중에도 즉시 반영)
make once       판단 1회만
make test       자체 점검
make liquidate  업비트 잔여 자산 전량 매도 (직접 실행, '실주문' 타이핑)

make entry      진입 정책 비교 (즉시매수 vs 하한 방어 vs 지정가·되돌림·학습)
make sweep      CONF·파라미터·기간 민감도 (과최적화 점검)
make quant      quant_nasq100 기법 이식 검증 (변동성 타겟팅 = 같은 수익에 MDD 절반)
make both       롱·숏 양방향 + 국면(상승/횡보/하락)별 승률 (결론: 롱 전용 유지)
make downside   숏 대안 3종: 짧은 청산선 · 반등 롱 · 실제 펀딩 (결론: 셋 다 음수)
make rev        고점 숏·저점 롱 평균회귀 10년 검증 + 나스닥 + 지표 기여도 (결론: 반대로 가는 신호였다)
make lat        갱신주기·AI 호출 지연 비용 (결론: 10분 적정, AI 는 체결 직전이 맞다)
make bias       비판적 검증: 추세편향·중복표본·순열·다중검정 (결론: EXTREME_MIN 은 근거 부족 → 0 권장)
make current    지금 .env 설정 그대로의 수익률·승률·롱숏 비율 (설정을 직접 읽으므로 봇과 어긋나지 않는다)
make sexit      숏 청산 재설계 14종 × 진입 2종 (결론: 28조합 전부 음수. 승률 55% 로 올려도 기대값은 음수)
make flow       매수/매도 흐름 패턴 — 바이낸스 taker 실측 7년 (결론: 흐름은 관성, 반복되는 건 거래량뿐)
make minutes    1분봉 전량 내려받기 (약 2시간, 끊겨도 이어받음)
make learn      분봉 지표 학습 → 워크포워드 평가
```
사이징: 명목 = 자산 × POSITION_PCT × lev. lev 는 변동성 타겟팅이 정한다 — 계좌 실현변동성이 `VOL_TARGET_PCT`(40%)를 넘으면 그만큼 깎고 올리진 않는다 (상한 `LEVERAGE`). research_quant_transfer.txt: MDD −42.5%→−22.4%, Sharpe(검증) 0.80→1.29. `VOL_TARGET_PCT=0` 이면 예전처럼 고정.
안전장치: 레버리지 5배 초과면 시작 안 함 — `make current --lev` 로 잰 근거 (2026-09-10 엔진 수정 후 재측정): 고정 5배·7배는 104건 전부 살아남고 **10배부터 전액 청산**된다 (진입 후 최악 역행 −10.1% = 이론 상한 9.9배). 예전에 적혀 있던 "7배부터 청산·상한 6.8배" 는 수정 전 백테스트 엔진의 허위 청산이었다 (audit/AUDIT.md). 변동성 타겟을 켜면 상한 10배라도 실제 평균 2.6배라 살아남지만 Sharpe 가 1.36→0.86 으로 나빠진다, 24시간 고점 대비 −30%(MAX_DAY_LOSS_PCT)면 청산 후 자동실행 정지 (재개 `make on`).
Claude 검토: **주문 직전**에만 OmniRoute(http://localhost:20128) 경유로 호출해 알고리즘 값을 대조·거부한다 (instructions.md).
자리가 났을 때가 아니라 분봉이 진입선을 지켜 체결이 확정된 순간에 부른다 — 검토와 체결이 최대 4시간 벌어지던 것을 붙였다. `make run` 이 OmniRoute 도 띄운다.
모의 3단계: 모의 장부(paper) → OKX 데모(OKX_DEMO=1) → 실계좌(OKX_DEMO=0). 설정은 .env.example 참고.
