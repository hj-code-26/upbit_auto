## 2. 항목별 상세

### P0-1 설정

- **[코드]** 적용 우선순위: `rls.py` 상수 < 환경변수 `MODE`, `RLSC_TRANCHES` (`load_dotenv()` 는 이미 있는 환경변수를 덮지 않음 → systemd `Environment=` 가 `.env` 보다 우선). 실행 인자는 설정을 바꾸지 않는다. 서비스 설명 문자열은 코드가 읽지 않으므로 모드의 근거가 될 수 없다.
- **[코드]** `margin = realized × MARGIN / N` (`open_tranche`) — 몫마다 2% 를 중복 적용하지 않음을 확인. 리플레이(`simulate_tranches`)는 자본을 N 등분해 각 몫이 자기 자본의 2% → 같은 관계. 10% 동시 한도는 코인 2종 × 2% = 4% 라 코인만으론 걸리지 않는다.
- **[수정]** `rls.strategy_config()` 한 곳에서 상품·몫 경계·레버리지·종목당/몫당 증거금·동시 한도·신호 규칙 버전(`RLS-C1`)·위험 정책 버전(`R2`)·손절 발동 가격(`last`)·수수료·펀딩·슬리피지 모델을 만든다. 운용(`autotrade.CFG`)과 리플레이(`backtest.coin_run`)가 같은 함수를 쓰고, `config_hash`(12자리)와 `config_diff`(필드별 차이)를 제공한다 — `rls.py:42-68`.
- **[수정]** `autotrade.effective_config()`/`code_version()` (`autotrade.py:134-155`): 모드·전략 설정·해시·git HEAD·미커밋 여부·실행 파일 해시. 인증 정보는 넣지 않는다 (T16 이 환경변수에 키를 넣고 출력에 없음을 확인). 작업 시작 로그·대시보드·백테스트 manifest 에 해시와 코드 버전이 들어간다. 지금 작업 트리는 `dirty: true` 로 표시된다.

### P0-2 위험 감지 → 청산 → 잔여 수량 확인

- **[수정]** `risk_step` (`autotrade.py:244`)을 모든 작업(t0/t1/t2/guard/risk) 맨 앞에서 실행. `schedule_forever` 가 작업 사이에 `RLSC_RISK_POLL_SEC`(기본 demo/live 5초, dry 60초)마다 `run_job("risk")` 를 돌린다. 감지 즉시 같은 회차에서 `flatten` 을 호출하므로 감지→최초 청산 요청은 같은 감시 1회 안이다 (네트워크 왕복 제외 목표 10초 이내; 실측은 demo 필요).
- **[수정]** 상태 흐름 (kv `risk`): `RUNNING → HALTING`(진입 금지를 먼저 기록) `→ FLATTENING`(거래소 잔여 수량 기준 청산) `→ HALTED`(봇 수량 0 확인 뒤에만), 실패 시 `DEGRADED`(재시도). 내부 지표 `t.last_ok / last_check / detected / flatten_req / flat_ok`, 판정 시 자산 대비 손실(`flat_eq`).
- **[수정]** `flatten` (`autotrade.py:638`): (상품, 방향)마다 봇 몫 합산 수량과 거래소 현재 수량 중 작은 값으로 주문 1건. 봇 장부보다 많은 거래소 수량은 건드리지 않는다. 보호 손절은 먼저 취소하지 않는다 (헤지 모드 `posSide` 청산 주문은 반대 포지션을 만들지 않음 — Paper 도 포지션 없으면 51169 거부). 부분 체결이면 같은 회차에 최대 3번 남은 수량만 다시, 그래도 남으면 FLATTENING 유지.
- **[수정]** 신규 진입은 (1) 작업이 신호 판정 때 `entry_blocks` 확인, (2) `open_tranche` 가 **주문 직전에 kv 의 위험 상태를 다시 읽어** 확인 (다른 프로세스가 기록한 사유 포함, T02).
- **[수정]** 락: 작업·감시 모두 같은 비차단 flock. 같은 프로세스에선 차례로 실행되므로 겹치지 않고, 다른 프로세스가 락을 쥐면 그 감시 1회를 건너뛰며 120초 넘게 못 잡으면 경보. HTTP timeout 10초·재시도 상한 5회는 기존 그대로.
- **[제안]** 위험 감시가 작업 실행 중(보통 수 초, 주문 확인 대기 최대 10초 × 재시도)에는 돌지 않는다. 작업 시간이 길어지는 경우(최초 `seed_edge` 다운로드 등)를 demo 에서 측정할 것.

### P0-3 손실 기준·재시작

- **[결정]** 일손실 기준은 **UTC 날 경계 판정**을 유지한다 (기준 = UTC 00:00 직후 첫 감시 기록, 예전 00:02 t0 기록 대체). 장중 −5% 상시 판정으로 바꾸면 과거 리플레이에서 일손실 청산이 31/341건(c3-l30)인 '이익 반납 청산' 규칙이 달라져 백테스트와 운용이 어긋나기 때문이다. 리플레이의 00:00 기록과 같은 규칙이다. 킬(−35%)만 상시 판정으로 바꿨다 (과거 구간 미발동 → 수치 영향 없음). 위험 정책 버전 `R1 → R2`.
- **[수정]** `risk_eval` (`autotrade.py:212`): 이전 기간 판정을 끝낸 뒤 새 기준 생성, 기간당 1번 (재시작해도 같은 날이면 다시 만들지 않음), 기준 기록이 00:00 보다 15분 넘게 늦으면 그날 신규 진입 보류(`day_ref_late`), 다음 날엔 일손실 사유만 해제 (킬·강제청산·불일치 등 유지, T06/T07). HWM·사유·기준은 kv 에 영속 (재시작·날짜 변경으로 초기화되지 않음).
- **[수정]** 입출금: `okx.Client.transfers` (bills type 1 = 거래 계정 이체) 로 순이체를 구해 일 기준·고점을 같은 금액만큼 옮긴다 (현금흐름 조정). 조회 실패 = `stale` 진입 차단·DEGRADED (T08/T13). **[제안]** bills 의 type/필드 정의를 demo 에서 확인 — 입금이 펀딩 계정에만 있고 이체 전이면 거래 계정 자산에 영향이 없으므로 무시해도 된다.
- **[코드]** 연패 정의: 비용 포함 순손익 ≤ 0 이면 패 (본전도 패), 몫·부분 청산마다 1건, 청산 기록 순서대로. 20 은 과거 최장 18 을 보고 정한 값이다 (패치 문서) — 미래 상한이 아니다 (경보 문구에 반영). 시험 손실 예산은 **미설정** (수치를 임의로 정하지 않음 → 소액 live 판정 미완료 사유).

### P0-4 장부·포지션·손절 정합

- **[수정]** 주문 생명주기 `submit → apply_fill → commit` (`autotrade.py:457-546`): 주문 전에 미확정 기록을 저장, 체결 확정 수량(`accFillSz`)만 장부 반영, 장부 저장과 미확정 해제·반영 기록(`applied`)을 한 SQLite 트랜잭션으로. 응답 유실·확인 실패면 다음 대사(`reconcile`)가 clOrdId 로 확정하고, 그 전엔 그 상품에 새 청산 주문을 내지 않는다. 새 주문은 `fresh_cid` 로 이미 반영된 clOrdId 와 겹치지 않게 (같은 날 재시도가 옛 체결을 다시 반영하는 경로 차단). T03/T05.
- **[수정]** 부분 청산은 `split` 으로 몫에서 떼어 거래 1건으로 기록하고 나머지를 남긴다. 귀속이 불명확한 거래소 수량은 몫에 배분하지 않고 `mismatch` 진입 차단.
- **[수정]** `ensure_stops` (`autotrade.py:713`): 같은 방향 몫 전부를 그 순간 거래소 청산가로 재검사 (T09), tick 은 진입가 쪽 반올림 (T17), 현재가를 넘었거나 청산가와 여유가 없으면 그 몫 청산 (6.2.5/6.2.6), 새 손절은 조회로 확인, 옛 손절 취소 실패는 `stop_old` 로 추적·다음 점검에서 재취소·진입 차단 (T10), 손절·청산 모두 실패하면 `unprotected` 진입 차단 + 위험 감시가 즉시 재점검 (T11), 봇 소유가 아닌 조건부 주문은 취소하지 않음 (T12).
- **[코드]** `close=True` 는 내부 인자: `side = buy/sell`, `posSide = long/short`, `ordType=market`, `tdMode=isolated` 로 매핑됨을 확인 (`okx.py` `order`). 손절은 `ordType=conditional`, `slOrdPx=-1`, `slTriggerPxType=last` 를 명시 (`okx.py:247`). last → mark 변경은 하지 않았다 (신호·리플레이와 함께 바꿔야 함).
- **[코드]** 청산가 근사 `1/L − 티어1 MMR − taker` 는 리플레이·Paper·손절 상한에만 쓰이고, 운용 손절은 거래소 `liqPx` 로 다시 검사한다. 티어1 최대 수량 초과 검사는 없다 — **[제안]** 명목이 티어1 `maxSz` 에 가까워지면 추가 (현재 최소 자금 수준에선 해당 없음).

## 3. 신호 규칙 보존
