### 채택 후보: 변동성 타겟팅 (유일하게 두 구간 모두에서 이겼다)

계좌 일별 수익률의 실현 변동성을 연율화해, 목표를 넘는 만큼 진입 레버리지를 깎는다.
  lev = min(3, 목표% / 실현변동성%)          — 저쪽 autotrade.exposure_cap() 과 같은 계산 (깎기만, 올리진 않음)
레버리지는 진입 시점에 정하고 그 거래 동안 고정한다. 거래소가 포지션 단위로 레버리지를 걸기 때문이다.

  3배 +VT(계좌) 40%·창60일   +49% / -27.0% / 1.31   |   +27% / -32.0% / 0.73   |   +491% / -32.0% / 1.02
  → **CAGR 은 두 구간 모두 고정 3배와 같은데 MDD 만 -44.6→-27.0 / -51.7→-32.0 으로 줄었다.**
     Sharpe 0.77→1.31 (탐색), 0.43→0.73 (검증). 최악 거래 -17.5%→-12.4%. 거래 수·승률은 그대로(108회·34%).
     공짜로 위험만 절반 깎였다. 수익을 포기하고 산 안정이 아니다.
  → 더 중요한 것: 이때 **평균 레버리지는 1.55배**다 (중앙값 1.39, 3배를 그대로 쓴 진입은 108회 중 14%뿐).
     고정 1배가 +21%/+13%, 고정 2배가 +37%/+22% 이므로 '평균 1.55배' 를 고정으로 쓰면 대략 +28%/+17% 다.
     타겟팅은 그 절반 남짓한 위험 예산으로 고정 3배와 같은 +49%/+27% 를 냈다 — 레버리지를 줄인 게 아니라
     **레버리지를 값이 나가는 자리에만 놓은 것**이다. (타겟30%·창120일이면 평균 1.25배로 +45%/+30%.)

견고성 (타겟 15~50% × 창 40~120일, 20조합)
  · 20조합 전부에서 MDD 가 기준선보다 개선됐고, 검증 구간 Sharpe 도 20조합 전부 기준선(0.43)을 이겼다
  · 탐색 구간 Sharpe 는 창90일 · 낮은 타겟(15~30%) 3조합에서만 기준선(0.77)에 못 미쳤다 (0.63~0.75)
  · 창60일 30~50% / 창120일 30~50% 는 두 구간 모두 기준선을 이긴다 — 한 점에 걸린 결과가 아니다
    창120일 50%:  +61% / -32.3% / 1.49  |  +38% / -29.1% / 0.98  |  +826% / -32.3% / 1.24
    창120일 30%:  +45% / -30.0% / 1.34  |  +30% / -22.8% / 0.97  |  +487% / -30.0% / 1.17
  · 타겟·창을 어디로 잡든 방향이 같다는 것이 요점이고, 정확한 값은 취향이다. 권고는 창60~120일 · 타겟 30~40%.

주의 — BTC 변동성 기준(계좌 대신 BTC 자체의 실현변동성)으로 재면 위험은 줄지만 수익도 같이 준다:
  3배 +VT(BTC) 60%          +27% / -15.8% / 1.02   |   +21% / -27.3% / 0.65   |   +230% / -27.3% / 0.81
  계좌 기준이 나은 이유: 이 전략은 시간의 대부분을 현금으로 쉰다. 계좌 변동성은 '최근에 실제로 얻어맞았는가'를
  재고, BTC 변동성은 쉬는 동안의 변동성까지 재서 들어가지도 않은 위험으로 레버리지를 깎는다.


### 기각: 고정 만기 청산 (저쪽에선 채택, 여기선 노이즈)

보유 N일이 지나면 신호와 무관하게 판다. 저쪽에선 승률 56.4% 로 모멘텀 청산(42.1%)을 이겼다.
여기서는 이웃값이 전혀 안 붙는다 (3배 기준 전체 Sharpe, 기준선 0.60):
  만기 1일 0.49 · 2일 0.23 · 3일 0.70 · 4일 0.76 · 6일 0.41 · 8일 0.79 · 10일 0.57 · 20일 이상 = 기준선
  3일·4일이 좋아 보이지만 2일과 6일이 기준선보다 나쁘다. 부호가 이웃에서 뒤집히면 그건 규칙이 아니라 노이즈다.
왜 저쪽과 다른가: 저쪽 봇에는 구조 청산이 없어서 만기가 유일한 청산이었다. 코인 봇에는 이미
4h 6봉 저가 이탈이라는 구조 청산이 있고, research_okx_short.txt 에서 그게 엣지의 본체로 확인됐다.
같은 일을 하는 규칙을 하나 더 얹는 것이라 새로 얻는 게 없다.

### 워밍업(자산 이력이 20일도 없을 때)은 그냥 LEVERAGE 로 둔다 — 재보고 내린 결론
계좌를 새로 시작하면 반드시 지나가는 구간이라 대체값을 넣을까 재봤다. 전부 현재 방식보다 나빴다:
  워밍업 → 3배 그대로 (현재)   검증 1.29 / 전체 +1,027% / MDD -22.4%   ← 최고
  워밍업 → BTC 변동성으로      검증 0.97 / 전체   +378%
  워밍업 → 2배로 낮춤          검증 1.02 / 전체   +654%
  워밍업 → 1배로 낮춤          검증 0.98 / 전체   +456%
MDD 는 넷 다 -22% 대로 같고 수익만 깎인다. 워밍업에 레버리지를 낮추는 것은 위험을 줄이지 못하고 수익만 버린다.
전체 진입 104건 중 25건이 워밍업·무거래로 타겟팅 없이(=상한 그대로) 들어갔고, 그래도 위 성적이 나온다.

### 봇에 반영 (2026-09-10)
autotrade.target_leverage() — `.env` 의 VOL_TARGET_PCT(40) · VOL_WINDOW(40). 진입 직전에 매번 다시 계산하고
그 거래 동안 고정한다. runs 표의 날짜별 마지막 자산으로 실현 변동성을 재며, 열은 live 여부에 따라
real_equity / paper_equity 를 골라 축척이 섞이지 않게 한다. 이력이 30일보다 짧거나 변동성 0 이면 대기(LEVERAGE 그대로).
거래소 레버리지는 정수라 ceil(lev) 로 걸고 명목으로 lev 를 맞춘다 → 증거금이 더 들어가 실제 청산선은 더 멀다.
VOL_TARGET_PCT=0 이면 예전처럼 고정 레버리지.
